# Percentage-closer soft shadows (PCSS)

## Sources and scope

Fernando's SIGGRAPH 2005 contribution is a technical sketch: blocker search, parallel-plane penumbra estimate, then percentage-closer filtering (PCF). NVIDIA's 2008 integration whitepaper is a production implementation reference, not a paper; it recommends raw depth for blocker search and a comparison-linear sampler for the final filter. [2005 sketch](https://developer.download.nvidia.com/shaderlibrary/docs/shadow_PCSS.pdf), [2008 whitepaper](https://developer.download.nvidia.com/assets/gamedev/docs/PCSS_Integration.pdf). GPU Gems 11 describes hardware PCF as four depth comparisons and bilinear interpolation per linear comparison-sampler lookup; this accelerates PCF, not blocker search or penumbra estimation. [GPU Gems 11](https://developer.nvidia.com/gpugems/gpugems/part-ii-lighting-and-shadows/chapter-11-shadow-map-antialiasing).

## Chosen first variant

For a finite area light, use raw light-space depth for the blocker search. A tap is a blocker when it is closer to the light than the receiver by more than the chosen bias. Average blocker depths and estimate the penumbra under the parallel-plane approximation:

```text
w_penumbra = (d_receiver − d_blocker) × w_light / d_blocker
```

Here `d_receiver` and `d_blocker` are distances from the finite emitter, not arbitrary normalized depth values. Convert the estimate to a bounded PCF kernel in shadow-map texels. If no blocker is found, return fully lit without dividing. Keep blocker-search and filtering budgets independently bounded; use a fixed sample pattern for deterministic output. Bias must be tuned for both blocker classification and PCF, since a wide filter can expose self-shadowing.

### Directional-light CSM variant

Do **not** apply the finite-emitter equation above directly to a directional light. A normalized orthographic cascade depth is linear but has an arbitrary near-plane offset; using it as `d_blocker` makes the result depend on cascade depth bounds, and an angular light size is not the finite `w_light` in the original equation.

For the first directional variant, define the source as an angular **radius** `α` in radians. Convert receiver-minus-average-blocker depth from `[0,1]` to light-space distance `Δz` using that cascade's light-depth range. The distant-source angular approximation gives a penumbra radius:

```text
r_penumbra ≈ max(Δz, 0) × tan(α)
```

This follows from the angular spread of rays across the blocker-to-receiver separation; it is a derived directional-light variant, not Fernando's original finite-light formula. A conservative search radius is `r_search = min(r_max, max(z_receiver − z_min_caster, 0) × tan(α))`, where the depths are light-space distances and `r_max` is the configured world-space cap. Convert both radii to UV using the cascade's orthographic width and height; cap the PCF kernel and keep taps within the selected layer. If the bound clips at cascade edges, add and validate overlap/blending rather than silently sampling another layer.

X173GE uses sixteen blocker taps and sixteen final comparison-sampler taps. Both loops share a precomputed Vogel disk table, including the `sqrt((i + 0.5) / 16)` radial stratification, so tap count and distribution are unchanged without per-tap square roots. The taps are rotated deterministically from a pixel-scale hash of the receiver's light-plane world position; no noise texture or new dependency is required. The shader reuses the already-computed orthographic light clip coordinate and removes its translation, avoiding another pair of world-axis dot products while keeping the hash field independent of the snapped cascade origin. Its world-space cell width follows the projected world footprint of one screen pixel, keeping the grain fine at close range instead of holding one rotation over a broad fixed cell. The cascade index is not part of the hash, keeping the phase consistent for the same light-plane position across cascade selections. This derivative-scaled hash is an X173GE adaptation, not a PCSS paper default; its cell scale changes with camera distance and orientation, so review for crawling and scale transitions. The demo light uses a 0.50° angular radius and a 0.2-world-unit maximum penumbra. Raw blocker depth remains point sampled and is softly weighted across the receiver bias band before averaging, avoiding a binary all-lit/all-shadowed switch from one tap. Final PCF taps use Vulkan's linear depth comparison sampler, giving a 2×2 hardware PCF footprint per lookup. The depth format must advertise `SAMPLED_IMAGE_FILTER_LINEAR`; device selection rejects formats that cannot legally support this path. The receiver-depth footprint bias is computed once per fragment and reused by all filter taps. Independent sample offsets and fixed-loop unrolling remove the serial Vogel rotation chain and expose the taps for parallel texture scheduling. X173GE reconstructs blocker/receiver distances from each cascade's linear depth range and applies visibility only to the selected directional light's direct PBR term. The normalized constant depth bias is `max(2e-5 × (1 − N·L), 5e-6)`, so the corresponding world-space offset scales with the cascade depth range. These are engine choices, not paper defaults; reduced filter tap count is a performance/quality tradeoff and requires visual review against the reference model.

For a cascade matrix `M` with square orthographic half-extent `h`, recover its translation-free light axes as `r = h × row0(M).xyz` and `u = h × row1(M).xyz`. The shader obtains the same coordinate by removing the translation from its existing orthographic light clip value. For receiver position `p`, let `dx_uv` and `dy_uv` be derivatives of the projected shadow UV with respect to screen x and y. Quantize the light-plane coordinate at approximately one screen pixel:

```text
light_position = (dot(p, r), dot(p, u))
s = max(2h × max(length(dx_uv), length(dy_uv)), 1e−5)
g = floor(light_position / s)
rotation = 2π × hash(g)
```

This is an X173GE spatial hash adaptation. It deliberately omits screen position, matrix translation, and cascade index; the same world-space point and light direction use the same world grid. The cell width follows the current projected pixel footprint, so camera distance and orientation can rescale the grid; test for crawling while moving the camera. Wyman and McGuire describe pixel-scale, geometry-anchored hashed sampling for alpha testing, not PCSS, and discuss derivative changes during camera motion.

### Receiver-plane depth correction

The NVIDIA integration whitepaper's receiver-plane method offsets receiver depth at each PCF tap using the local light-space depth gradient `(dz/du, dz/dv)`. X173GE derives the gradient from screen-space derivatives of world position transformed by the selected cascade matrix, then solves the 2D UV Jacobian. The cascade matrices are affine orthographic, so clip `w` is always 1 and its screen derivatives are zero; the shader therefore uses the matrix's 3×3 transform directly instead of a redundant perspective divide and quotient-rule derivative. For raw blocker samples, resolve to the sampled texel center `uv_center` and compare `z_receiver + dot(gradient, uv_center - uv_receiver) - constant_bias` against that texel's stored depth. For the final linear comparison lookup, retain the sub-texel sample position and add a conservative gradient bias for the sampler's half-texel footprint; otherwise the 2×2 hardware comparisons would share one receiver depth across a sloped surface. A predicted receiver depth outside `[0,1]` is treated as an unshadowed tap. This replaces a kernel-size-dependent increase to a single constant bias and keeps the existing small constant term for raster/depth precision.

For opaque PBR and SSR receivers, gradients are evaluated from fragment derivatives before light-facing branches, so the calculation does not depend on derivatives inside divergent direct-light flow. MBOIT transmittance is multiplied after opaque PCSS visibility and does not change its receiver-plane comparison. The separate God Rays march supplies zero gradients because its per-pixel sample loop does not provide a uniform derivative domain; its opaque volumetric shadowing remains a constant-bias approximation. Assumptions for the surface path are a locally planar rasterized receiver and non-degenerate projected UV derivatives; a near-zero Jacobian falls back to zero slope correction.

Mittring's SIGGRAPH 2007 real-time rendering course chapter (a production reference, not a peer-reviewed paper) reports this same screen-locked-noise artifact during camera motion and replaces screen projection with mipmapped noise projected in world space along the sun direction. It notes that nearby shadow edges can become distorted by magnification, while the result looked better for foliage. X173GE uses a hash-only variant instead of adding a texture: it removes the selected cascade matrix's translation, converts its X/Y axes back to world units, and hashes the receiver's light-plane position at a derivative-scaled pixel footprint. This keeps the grain spatially attached without temporal history or an additional resource, though the scale can change as the camera moves. Wyman and McGuire's TVCG 2017 hashed-sampling paper supports world-space coordinates for stable hashing on static geometry and pixel-footprint scaling, but its algorithm is for alpha testing, not PCSS. No frame-varying phase is used; temporal sample variation would need a temporal reconstruction path that X173GE does not have. [Mittring, “Finding Next Gen—CryEngine 2,” SIGGRAPH 2007 course notes](https://www.advances.realtimerendering.com/s2007/Mittring-Finding_NextGen_CryEngine2%28Siggraph07%20Course%20Notes%29.pdf), [Wyman and McGuire, “Improved Alpha Testing Using Hashed Sampling,” TVCG 2017](https://cwyman.org/papers/tvcg17_hashedAlphaExtended.pdf).

The comparison scene is `../rebuild1/assets/model.glb`, especially its large floor and complex greenhouse meshes. Visual review must compare hard shadows, PCSS alone, and PCSS with MBOIT enabled; acne, detached shadows, cascade seams, filter grain, and receiver lighting remain human-reviewed outcomes.

The device creates one cleared 1×1 fallback depth map initially so every cascade descriptor is valid. Four 2048² maps are created, cleared, and bound only when the first frame requests shadows. This avoids reserving the full shadow memory for scenes that do not use a shadowed light. The allocation transition waits for the prior frame fence before changing descriptors; validation covers both the fallback-only and full-map paths.

The camera uses reverse-Z, but the separate light shadow maps use forward depth (`0..1`, clear `1`, `LESS`). Raw blocker samples are point sampled; a shadowed receiver has `receiverDepth - bias > storedDepth`. The comparison sampler uses `LESS_OR_EQUAL`, so its result is lit when the receiver reference depth is less than or equal to the stored map depth. The depth image must support depth-attachment, sampled, and linear-filter usage, and depth writes must be synchronized before fragment sampling. Vulkan 1.0 provides `VK_IMAGE_LAYOUT_DEPTH_STENCIL_READ_ONLY_OPTIMAL`; use it with a legacy pipeline barrier or render-pass dependency. [Vulkan image layouts](https://registry.khronos.org/vulkan/specs/latest/man/html/VkImageLayout.html), [image barriers](https://registry.khronos.org/vulkan/specs/latest/man/html/VkImageMemoryBarrier.html).

## Assumptions and validation

This estimates soft visibility for opaque casters under approximately parallel blocker, receiver and light planes; it is not exact area-light visibility. It applies to the direct contribution of the selected light only. The 2008 sample counts are measurements on historical GPUs, not current defaults. Choose counts after per-pass profiling; do not add translucent shadowing without a separate model and validation.

Use a fixed planar blocker and receiver. At `α = 0`, shadows should use one hardware-PCF footprint; with positive angular radius, sweep blocker height and verify the opaque-PCSS penumbra grows with light-space separation while contact remains sharp. Include an unblocked receiver, each cascade boundary and map edges. Check light leaks, acne, bias behavior, radius caps, world-anchored PCSS grain, and no-blocker handling. Move the camera laterally and vertically across a static receiver and repeat with MBOIT enabled; the opaque grain should follow the model and the transparent shadow should remain stable. Check derivative-scale changes, cascade transitions, and a moving rigid object separately. CPU checks and Vulkan validation cover matrix bounds and resource synchronization, but visual penumbra, grain, and bias review requires the real model.

## Performance check

On the Windows RTX 4070 SUPER, measure `clear` at 1280×720 with the rebuild1 benchmark camera, no environment/SMAA, 120 warmup presents, then 180 measured presents. The original 2.0° / 16-blocker / 32-filter version measured scene-pass p50/p95 at 0.0717/0.0768 ms and total GPU p50/p95 at 0.2526/0.2655 ms. The 0.60° / 16 / 16 version without cascade culling measured scene-pass p50/p95 at 0.0635/0.0707 ms and 0.0696/0.0768 ms across two runs; total GPU was 0.2450/0.2565 ms and 0.2628/0.2729 ms. `shadow::fit` already computes the conservative caster set from each mesh AABB's overlap with the cascade's light-space square, so the render pass now reuses those indices instead of submitting every item to all four cascades. On the same 16-tap version, `shadow_ms` p50/p95 was 0.1228/0.1267 ms and 0.1233/0.1299 ms across two runs; total GPU was 0.1953/0.2033 ms and 0.1964/0.2053 ms. In this benchmark view, each cascade previously submitted 174–175 opaque draws; the first two cascades had no overlapping casters and now submit none. The scene pass includes PBR work, but these runs show the largest repeatable gain came from avoiding off-map shadow draws: mean `shadow_ms` fell about 31% and total GPU time about 23%. The 16-tap filter still trades sampling density for speed and needs human visual review on the fixture. On 2026-11-14, precomputing the existing Vogel radii and using the affine orthographic cascade invariant measured `shadow_ms` p50/p95 of 0.0797/0.0832 ms and total GPU p50/p95 of 0.1562/0.1663 ms under the same 120/180 benchmark; the immediately previous approved shader measured 0.0916/0.0948 ms and 0.1638/0.1675 ms. This is a 13% shadow p50 and 5% total GPU p50 reduction, with no change to tap count or ideal sample positions; visual review with camera motion is still required.
