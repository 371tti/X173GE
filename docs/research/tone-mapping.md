# Tone mapping and automatic exposure

## Sources and implementation variant

Reinhard, Stark, Shirley, and Ferwerda's *Photographic Tone Reproduction for Digital Images* is the original research paper for the log-average luminance and key-value scale used here ([paper](https://web.tecgraf.puc-rio.br/~scuri/inf1378/pub/reinhard.pdf)). Goodnight et al.'s *Interactive Time-Dependent Tone Mapping Using Programmable Graphics Hardware* is a second research paper supporting GPU-side temporal adaptation ([paper](https://diglib.eg.org/bitstream/handle/10.2312/EGWR.EGWR03.026-037/026-037.pdf?isAllowed=y&sequence=1)).

X173GE uses the simpler per-channel Reinhard output curve, not Reinhard's full luminance-preserving photographic operator or white-point extension. It uses a GPU reduction pyramid to estimate log-average scene luminance and a first-order temporal response to adapt a scalar exposure gain. This is a practical variant inspired by the sources, not a claim of exact reproduction of either paper. A separate display-linear contrast control is a point operation added after Reinhard; it is not from those papers.

## Equations and assumptions

For each linear HDR pixel, compute Rec. 709 luminance `Y = max(dot(rgb, (0.2126, 0.7152, 0.0722)), 1e-6)` and its `log2(Y)`. The reduction pyramid stores `(mean_log2_luminance, coverage)`; each level combines up to four children weighted by coverage, preserving exact weighting for odd image extents. The final mean defines `Lavg = exp2(mean_log2_luminance)`.

The target gain is `Etarget = clamp(key / Lavg, min_exposure, max_exposure)`. The current demo defaults are key `0.1`, gain bounds `0.21..16.0`, and adaptation time constant `1.0 s`. After the first neutral frame, adapt with `E += (Etarget - E) * (1 - exp(-dt / adaptation_seconds))`, where `dt` is elapsed wall-clock time since the prior successful queue submission. These scene-tuned values are not mandated by the papers. The implementation smooths gain rather than adapting luminance, and does not implement the asymmetric, state-rich visual adaptation model from later work.

Apply exposure to linear HDR before the per-channel curve `m = c / (1 + c)`. Then apply display-linear contrast around the curve's 18% gray output, `p = 0.18 / 1.18`, with `m' = clamp(p + contrast * (m - p), 0, 1)`, and write linear display RGB to the sRGB swapchain attachment for display encoding. `contrast=1` is neutral and its allowed range is `0.5..1.5`; clipping at the range endpoints and channel-wise saturation shifts are expected limitations of this simple control. The measurement runs after SSR and God Rays and before Bloom, so bloom does not feed back into exposure. All reduction and history images are per surface generation, remain on the GPU, and require no CPU readback. The history ping-pong index and timestamp advance only after a successful frame submission; a recreated surface starts at exposure 1.

In the interactive `clear` example, compiled numeric renderer, lighting, shadow, environment, and camera controls are selected with Tab/Backspace, changed with Up/Down, and reset individually with Home. All 26 are present when every render effect is compiled. F2-F11 toggle the compiled render effects and demo lights/environment. F11 specifically toggles diffuse HDRI illumination; it does not enable environment-map reflections. The selected label and value are shown in the window title. Feature-specific values are retained while their effect is disabled and are sent through the renderer command queue when active.

## Validation

Use the unchanged `../rebuild1/assets/model.glb` with the HDR greenhouse environment. Compare the same camera and scene in a bright exterior view and a darker interior view, then move between them at several frame rates. Check that output stays monotonic and bounded, exposure changes smoothly without visible flicker or a long pumping delay, and no-bloom/bloom plus SMAA paths use the same exposure. For contrast, use a gray ramp with neutral and saturated patches and confirm that `contrast=1` is unchanged while higher/lower values alter separation around the 18% pivot. Repeat after resize and shutdown/reopen. GPU timing should report exposure separately from Bloom and post. Shader compilation, SPIR-V validation, and build are automatic checks; visual acceptance still requires human review of the actual model.
